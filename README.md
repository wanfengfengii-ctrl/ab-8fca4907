# 编钟残音 · 联合基频识别

博物馆修复师从一组带有环境杂峰的编钟残音中确认哪些峰属于同一口钟。
本应用的关键约束是：**服务端联合选择**严格递增且不重复的泛音序号与可
剔除杂峰，使**同一基频**同时落入所有采用峰的容差区间——而不是先把每个
频率各自除以"最接近"的泛音序号、再把彼此无法共同成立的结论拼接起来。

## 判定规则

给定 6–18 条按频率严格递增的峰值 `f_i`、每条允许偏差 `±tol_i`、候选
基频闭区间 `[F_lo, F_hi]`、最高泛音序号 `H`、最多可剔除杂峰数 `R`。
为每条**采用**峰选择正整数泛音序号 `h_i`（随录入顺序严格递增、不重复），
要求存在同一个 `f0` 使

```
|f_i - h_i · f0| ≤ tol_i     对所有采用峰同时成立
⇔  f0 ∈ ⋂_i [ (f_i - tol_i)/h_i , (f_i + tol_i)/h_i ] ∩ [F_lo, F_hi] ≠ ∅
```

且采用峰数至少为 `n - R`（即剔除不超过 R 条）。方案选择按以下优先级：

1. 采用峰数最多；
2. 最大相对误差 `max_i |f_i - h_i f0| / f_i` 最小；
3. 误差平方和 `Σ (f_i - h_i f0)²` 最小；
4. 仍并列时取按录入顺序最早的泛音序号方案（同位置"采用且序号小"早于"剔除"）。

### 为什么不能逐峰就近归属

就近取整 `h ≈ round(f_i/f0)` 是局部决策：某条峰的"最近序号"可能占用
后续峰唯一可用的序号槽。测试用例 `test_greedy_nearest_harmonic_trap`
中，1160 Hz 就近属于 h=12（f0≈96.7），但那会堵死 1300 Hz 的归属；
联合搜索改派 h=11，与其余峰共享 f0≈104，6 条峰全部成立。

## 算法（均为联合计算）

`app/solver.py`：

1. **端点扫描计数**：归属关系只在端点 `(f_i±tol_i)/h` 处变化；在每个
   端点上用"严格递增槽位贪心"（连续整数段上的经典最长递增匹配）求该
   f0 下最多能联合采用多少峰，一次扫描同时给出剔除预算内最大数 K 与
   无约束最大数 K*。
2. **二分最小最大相对误差** e*：判定收紧容差 `min(tol_i, e·f_i)` 后
   预算内是否仍能联合采用 K 条。
3. **精确枚举 + 四级选优**：在 e* 收紧容差的全部归属端点上精确枚举
   K 峰、剔除 ≤ R 的递增序号分配（真实紧容差数据中每条峰只有唯一可行
   序号，枚举量为 1），逐份解析求最优统一基频：
   - 令 `c_min,c_max = min/max h_i/f_i`，则
     `M(f0)=max(c_max·f0−1, 1−c_min·f0)`，最优 f0 为两线交点
     `2/(c_min+c_max)` 在交集上的投影；
   - 在保持 M 最优的闭区间内，SSE 最小点为加权最小二乘解
     `Σh_i f_i / Σh_i²` 的投影。
   极端宽容差对抗输入触发枚举上限时，改用有界的固定点 WLS 动态规划
   （前缀最小值优化 O(n·K·H)）扫描端点并沿 WLS 顶点下降，保证有界。
4. **无解证据**：无解时用无剔除约束的最大联合子集 K* 界定冲突峰——
   强制容纳峰 j 时最大联合采用数 `< K*` 者不属于任何最大联合解释，
   取其中录入顺序最早者报告，并附该峰各序号下互不相容的基频带。

## API

`POST /api/solve`（JSON）：

```json
{
  "frequencies": [300, 400, 500, 600, 668, 846],
  "tolerances": [1.5, 1.5, 1.5, 1.5, 1.5, 1.5],
  "f0_min": 95, "f0_max": 105,
  "max_harmonic": 12, "max_rejected": 1
}
```

返回统一基频、可行交集、采用/剔除峰、逐峰泛音序号与误差、无解证据。
输入非法返回 400；`GET /healthz` 为健康检查。

- 无解时 `feasible=false`、`solution.f0=null`，且 `peaks` **完整保留
  原始峰值与顺序**；`evidence.index` 指向按峰值顺序最早无法纳入任何
  剩余联合解释的峰。
- 页面提供两份示例：**可复原残音**（一口 f0≈100 的钟 + 1 条杂峰 668）
  与**无解残音**（两条互不相容的冲突峰、剔除预算不足）。

## 运行（Docker Compose）

```bash
# 默认宿主机端口 8080 → 容器 8000
docker compose up --build

# 自定义宿主机端口
HOST_PORT=9000 docker compose up --build
```

打开 http://localhost:8080 （或自定义端口）。

### 一次性 verify 服务

`docker compose up` 时会同时启动一次性 **verify** 容器：它等待 web 健康
检查通过后，执行代码单元测试（含独立暴力穷举对拍），再对健康端点、一份
可复原残音、一份无解残音做 API 冒烟，**以退出码报告结果后自行退出**
（web 继续提供服务）。只看校验结果：

```bash
docker compose up --build --abort-on-container-exit --exit-code-from verify
```

## 本地开发 / 测试

仅依赖 Python 3.11 标准库，无需安装任何第三方包：

```bash
python -m unittest discover -s tests -v
PORT=8000 python -m app.server
python verify.py --base-url http://127.0.0.1:8000
```
